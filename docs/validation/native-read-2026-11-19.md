# Native read stability checks, 2026-11-19

Implementation branch: `test/native-read-stability`, based on `8dde3b378ccb7b56db90e2ab7657902af0f81090`. These are development checks on native x64 Windows 10.0.26300, not formal minimum-system, ARM64, or frozen-candidate acceptance.

The three raw Windows operations now share a private bounded-buffer loop. Name buffers grow independently of failed enumeration output; ordinary-root data reads use the documented required-byte count. A cancelled retry stops before another allocation. The production Source contract and public CLI are unchanged. No dependency version or lockfile changed; windows-sys `Wdk_System_Registry` is enabled only for tests that construct exact raw fixtures.

Executed with Rust/Cargo 1.100.0 and warnings denied:

- rustfmt, x64 all-target Clippy and **43 ordinary tests** passed (34 library, six CLI, three VM helpers). The four global VM cases remained ignored. ARM64 all-target Clippy compilation passed; no ARM64 binary ran.
- Actual RegQueryValueExW calls against a new private application hive received two ERROR_MORE_DATA responses before a coordinated writer thread shrank the value and changed its type. The final result contained exactly the successful three bytes and unknown type. Continuous growth exhausted the initial attempt plus eight retries, with capacities 256, 513, 1027, 2055, 4111, 8223, 16447, 32895 and 65791 bytes; the stable value remained readable afterward.
- Value deletion, key deletion and atomic cancellation between attempts stopped immediately with the distinct expected errors. Deleted handles also caused native child/value enumeration to return Win32 1018, not end-of-list. Removing a real value/key after enumeration preserved diagnostics, returned status 2 and continued another readable root without inventing an unset default.
- Native enumeration retained a 255-unit child name, a 6001-unit value name and unpaired UTF-16 surrogates. A deliberately small internal test buffer exercised real name-buffer retries; production still starts at 256 units. Only ERROR_NO_MORE_ITEMS ended the native lists.
- Twenty-two saved data layouts round-tripped their exact type/bytes, including missing/extra terminators, odd UTF-16 byte counts, isolated surrogates, empty MULTI_SZ variants and malformed integers. Actual name/type/HEX/text/empty queries checked when interpretation was necessary, when another OR condition sufficed and how raw previews retained failures. Real malformed key/value names stayed lossless and were never matched through replacement characters.
- std::io::pipe supplied a real Windows pipe with its reader closed. Direct writes and a large BufWriter's flush both stopped the query/output path with status 2 and no further traversal. Query input was constructed; this does not establish an actual CLI pipeline or console-event result.
- Capacity-overflow and cancellation probes failed before the affected allocation/operation. Deliberate OS memory exhaustion was not attempted. All private hive handles closed and temporary directories were explicitly removed.
- Fresh cargo-deny 0.21.0 checks passed for both Windows targets, including test features/dependencies: advisories, bans, licenses and sources. RustSec commit `7133866a6b44d6d3e1994ae6a48a296553c3c3da`, fetched at `2026-11-19T12:59:49Z`; lock SHA-256 `4302706560ffc6a88cc84ff6e1850f16ff5abc906e1b87dfb540606d86caccfd`. No exception was added.

The first expanded malformed-data fixture used RegSetValueExW with unterminated string input. Repeated execution exposed a trailing NUL added during fixture construction. That failed run is retained, not counted as pass. The fixture now uses the existing NtSetValueKey binding with a counted name/data length and requires exact readback through the production Win32 reader. The VM helper's raw-write probe uses a raw type rather than violating Win32 string-writing preconditions. See [test methods and primary API references](../testing.md).
