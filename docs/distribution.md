# Distribution materials

RegQry's own source, scripts and documentation use the MIT license in the package's `LICENSE`. Executables also contain third-party code and data. `THIRD-PARTY-NOTICES.txt` contains the original license texts selected by cargo-about 0.9.3; `licenses/materials.json` records the exact target, production or test scope, dependency versions/features, tool/config/input hashes and collected files. Additional packaged license/notice files are retained under `licenses/crates/`.

User ZIPs include the production/build dependency graph, including transitive dependencies. Test ZIPs also include development dependencies used by the distributed test executables. Material collection uses the actual extracted Cargo archive and the same default root features as compilation. It is separate from cargo-deny's dependency policy checks.

The repository's `about.toml` and `about-tests.toml` use cargo-about's hash-checked clarifications for lowercase Microsoft `license-mit` files. The test configuration retrieves difflib 0.4.0's omitted LICENSE from [its fixed upstream commit](https://github.com/DimaKudosh/difflib/blob/8748d65b8c631a244af70f9d9f0339b6e7e9d29c/LICENSE), checking SHA-256 `6725d1437fc6c77301f2ff0e7d52914cf4f9509213e1078dc77d9356dbe6eac5`. A failed retrieval, changed clarification, unsatisfied license, generic fallback without an original source, or missing graph entry fails collection. Generated files are frozen with their executables; they are not regenerated during release promotion.

`licenses/rust/COPYRIGHT-library.html`, `LICENSE-MIT` and `LICENSE-APACHE` are copied from the actual pinned Rust 1.100.0 toolchain. Rust's [copyright guidance](https://github.com/rust-lang/rust/blob/1.100.0/COPYRIGHT) identifies this HTML file as the standard-library subset, including its own dependencies. It is intentionally broader than a particular Windows executable and preserves upstream notices without trying to infer which individual source fragments the linker retained. The Rust compiler, Cargo, cargo-about and MSVC tools themselves are not distributed.

Jiff's Windows production graph includes `jiff-tzdb`, embedding IANA time-zone data. Its packaged COPYING/MIT/Unlicense notices accompany the graph. Consult the [IANA database description](https://www.iana.org/time-zones) and the exact crate's supplied license files rather than assuming all data is covered by RegQry's MIT license.

Windows ZIP executables explicitly link the release MSVC CRT statically. Microsoft describes [static deployment](https://learn.microsoft.com/en-us/cpp/windows/deployment-in-visual-cpp) and [runtime redistribution terms](https://learn.microsoft.com/en-us/cpp/windows/redistributing-visual-cpp-files). The build toolchain and SDK must be used under their applicable licenses. This package carries no separate Microsoft runtime DLLs, redistributable installer, debug runtime, SDK or Windows system DLL; imported DLLs are supplied by Windows. A release review must check the actual recorded MSVC/SDK environment and any newly introduced native/static dependency or bundled asset. Cargo dependency policy does not establish those rights.

There are no bundled fonts, images, shell executables or other third-party UI assets in the current user or test package. Scripts invoke an existing Windows shell and, when required, an existing PowerShell 7 installation. Test harnesses generate private fixtures at runtime. Changing this inventory requires reviewing and retaining the new material's notices before freezing a candidate.

Development asset builds are unsigned and are not formal release acceptance. Their file hashes establish byte identity; they do not provide Authenticode publisher identity. Minimum-system, clean-system, native architecture and release evidence must still pass before publication.
