# RegQry development test bundle

Extract the whole ZIP, then run `./run-tests.ps1` from Windows PowerShell 5.1 or PowerShell 7. Use `-ReportDirectory C:\path\to\new-results` to choose a new results directory outside the bundle. The default is a fresh directory under the current user's temporary directory. No Cargo, rustc, Build Tools, network access, elevation, or globally navigable registry fixture is required.

The runner checks every declared file's SHA-256 and rejects extra files before starting the CLI or test executables. Pass `-ExpectedManifestSha256 HASH` to check the manifest against a separately retained identity. Keep that hash and the original ZIP hash with external evidence; these hashes establish byte identity, not publisher authentication. The target must match native Windows architecture. Emulated execution is rejected for this check.

The bundle contains the actual CLI, Rust test harnesses, their complete test inventory, DLL import/header reports, and runner scripts. Ordinary tests use memory, temporary files, and a private application hive that unloads when its handles close. Ignored tests stay ignored and are recorded separately. Reports contain the bundle/source identities, actual Windows version, process/native architecture, token elevation, PowerShell version, harness arguments, exit codes, and captured UTF-8 streams.

`run-vm-tests.ps1` separately invokes the ignored real ROOT/view/ACL/link suite. Use it only in a disposable VM: elevated `-Phase Prepare -DisposableVm -QuerySid SID -RollbackReference REFERENCE -ContextPath PATH`, then non-elevated `-Phase Query -DisposableVm -ContextPath PATH` as that query user. The same verified bundle is required for both. The user hive must be loaded, the context parent must exist, and reports/context stay outside the bundle. Preserve records and roll back/destroy the VM even after a failure; there is no recursive registry cleanup. Full instructions and fixture scope are in `docs/vm-testing.md` in the source archive.

A timeout is a test failure, not a completed query. A successful run verifies this test layer on the recorded machine. It does not prove the formal minimum/clean-system, ordinary-user, real-console, or release matrix. These development bundles are not frozen release candidates and are not public release assets; final release packaging must add the reviewed third-party distribution materials.

The ordinary suite also creates a hidden isolated console and job to test process control with a constructed producer. CONTROL_PROBE metrics verify the apparatus, not RegQry query performance. The separate ignored VM suite includes actual CLI streaming, Ctrl+C, closed-pipe and long-result cases; they require the same prepared disposable VM and remain distinct from these ordinary probes.

Ordinary shell checks invoke the actual CLI in cmd and Windows PowerShell 5.1, plus installed PowerShell 7 when found. Pass `-PowerShell7 C:\path\to\pwsh.exe` to either runner, or set `REGQRY_TEST_PWSH` to that absolute path. Missing PowerShell 7 is explicitly `not-run` in ordinary test logs, never three-shell acceptance; an invalid explicit path fails. CI supplies its actual PowerShell 7 executable. These 16 cases per shell use only help/version and invalid input, including validation-only versions of the query commands. They do not search the workstation registry. Raw scripts, shell versions, output bytes and immediate exit codes are preserved as SHELL_FILE records in the harness log.

The VM query phase additionally requires all three shells and uses the owned Unicode/space-named fixture for successful/zero/partial queries, literal backslashes, empty names/patterns, leading hyphens, percent/dollar literals, regex quotes and explicit environment expansion. Its encoding checks cover PowerShell object capture, `Out-File -Encoding utf8` and native redirection. The isolated worker owns its console/code page changes; no caller profile, persistent setting or console is changed. Manual 80/120-column layout and physical keyboard Ctrl+C remain separate: copy `terminal-validation.md` outside the bundle and fill it with actual observations. The shipped template is all `not-run`.

`dll-imports.json` records direct and delay-load imports inspected by MSVC dumpbin. Static CRT and reviewed system imports are required. This does not prove dynamically loaded DLLs, imported API availability, or clean minimum-system execution.
